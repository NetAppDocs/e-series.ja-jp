= EシリーズのLinux ホストでNVMe over RoCEを使用してフェイルオーバーを設定する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージアレイへのパスを冗長化するには、フェイルオーバーを実行するようにホストを設定します。

.作業を開始する前に
 https://mysupport.netapp.com/matrix["NetApp Interoperability Matrix Tool で確認できます"^]を参照して、必要なアップデートがすべてインストールされていることを確認してください。初期リリースには含まれていないSLESまたはRHELのバージョンでは、重要なバグ修正が必要になる場合があります。

.このタスクについて
SLES 15、SLES 16、RHEL 9、RHEL 10 では、ネイティブ NVMe マルチパスはデフォルトで有効になっており、追加の構成は必要ありません。



[[configure-nvme-io-policy]]
== NVMe I/O ポリシーを設定する

.このタスクについて
Linux NVMe ネイティブマルチパスはデフォルトで `numa` I/O ポリシーに設定される場合があります。Eシリーズ/EFシリーズの NVMe-over-Fabrics 構成では、推奨される I/O ポリシーは `round-robin`であり、これにより利用可能なすべてのパスに I/O が均等に分散されます。

.手順
. 現在のNVMe I/Oポリシーを確認します：
+
[listing]
----
# cat /sys/module/nvme_core/parameters/iopolicy
numa
----
. 次のいずれかの方法を使用して、 `round-robin` I/O ポリシーを設定します：
+
** *永続的（推奨）* — udevルールファイルを作成します：
+
.<code>/etc/udev/rules.d/71-nvme-io-policy.rules</code>
[listing]
----
ACTION=="add|change", SUBSYSTEM=="nvme-subsystem", ATTR{iopolicy}="round-robin"
----
+
次に、ルールを再読み込みして適用します。

+
[listing]
----
udevadm control --reload
udevadm trigger --subsystem-match=nvme-subsystem
----
** *起動時のグローバル設定* — 以下のカーネル パラメータをブートローダーの設定に追加してください：
+
[listing]
----
nvme_core.iopolicy=round-robin
----
** *非永続的（オンライン、I/Oの中断なし）* — 再起動せずにすぐに適用します：
+
[listing]
----
echo "round-robin" > /sys/class/nvme-subsystem/nvme-subsys0/iopolicy
----
+

NOTE: この設定は再起動後も保持されません。
